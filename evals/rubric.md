# 诊断报告质量评分表（rubric）与回归测试说明

诊断报告无法用脚本能跑的断言验收，用这份 rubric 评分。每份产出报告按 10 项打分，每项 10 分，满分 100。≥80 分合格；任何带 ★ 的项目得 0 分，整份报告判不合格，退回重做。

## 评分项

| # | 项目 | 10分标准 | 0分情形 | |
|---|------|---------|--------|---|
| 1 | 入象 | 明确判定四象之一且给出水火依据 | 无入象或四象全提不判定 | ★ |
| 2 | 断链 | 明确指出断在哪一环且给数据依据 | 泛泛说"多环节有问题" | ★ |
| 3 | 顺行 | 修复顺序从断环起、金→水→木→火→土无跳环 | 出现跳环（如木断直接点火） | ★ |
| 4 | 度判定 | 五环每环都有过/不及/得度判定与读数 | 三处以上缺度判定 | |
| 5 | 取证 | 判定均能回溯到用户数据或明确标注"待补充" | 凭空下判 | |
| 6 | 处方可行 | 每环处方具体可执行、不超客户执行力 | 处方是空话（"加强品牌建设"式） | |
| 7 | 土指标 | 验收标准含复购率/自然流占比/老客占比当前值→目标值 | 缺任一项或只有当前值没有目标值 | ★ |
| 8 | 边界 | 不修命、不承诺爆发时辰，免责节完整 | 出现"三个月必爆"类承诺 | |
| 9 | 案例引用 | 引用二百四十案时注明"同构参考"，不贴标签 | 强行对标或盖棺定论 | |
| 10 | 输出规范 | 现代汉语行文+HTML格式（水印+主标题含品牌名+SVG嵌入HTML+落款免责声明） | 文言腔/无水印/SVG退化为Markdown/缺落款 | ★ |

> ★ = 一票否决项。该项 0 分，整份报告直接判不合格，不论其他项多高。

## A/B 盲评（改版时用）

1. 同一输入，分别用旧版和新版 skill 各出一份报告
2. 隐去版本标记，交给一个独立 AI 按上表评分
3. 新版总分须 ≥ 旧版，且 ★ 项不得新增失分；新版胜率 ≥60% 才算这次改版成立

## 回归测试（负迁移检查）

每次改版后必须回答三个问题：

1. **旧能力还在吗**：用 v1.0 就能出的标准诊断报告（如钟薛高案例，见 evals/case-zhongxuegao.md），新版还能不能出、质量是否不降？
2. **旧触发还准吗**：跑 evals/trigger-tests.md，对比上一版通过率，不得下降。
3. **新功能过度了吗**：新增的判定维度（度、三刀）是否在不该出现的场景被强行套用？例如用户只想聊竞品，新版是否非要给人家全套入象？出现即记为负迁移，收紧相应触发措辞。

## 人工审查（最后一环）

自动化告诉你"对不对"，人告诉你"好不好"。规则：空反馈 = 认可，有具体抱怨 = 改进点。只改有人抱怨的地方，不做想象中的优化。
