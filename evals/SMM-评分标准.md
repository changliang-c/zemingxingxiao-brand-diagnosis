# SMM — Skill 成熟度模型（Skill Maturity Model）

> **版本**: 1.0 | **创建日期**: 2026-08-16 | **适用Skill**: 择命行效（及其他 WorkBuddy Skill）
>
> **用途**: 每次改版后按本标准评分，出一张雷达图与上一版对比，让「水平变好了/变差了」从感觉变成数字。

---

## 一、五级体系（L1–L5，L5 为满级）

| 级别 | 名称 | 核心标志 | 一句话 | 典型状态 |
|------|------|----------|--------|----------|
| **L1** | 原型 | 能触发、有基本输出 | "能跑" | 写了 SKILL.md，模型能识别触发词，按指令给了段输出——但流程不全、没有测试、没有文档 |
| **L2** | 功能完整 | 完整诊断链跑通、frontmatter 规范、有 README | "流程全" | 从触发到交付的完整链路都能走完；frontmatter 含 name/description/version/agent_created；有 README 说明用途 |
| **L3** | 质量可控 | 静态测试≥80项、有 rubric、有回归案例 | "测得过" | 有可自动运行的静态测试套件且≥80项全绿；有人工阅卷 rubric 评分表；有至少1个回归测试案例（Fixture） |
| **L4** | 生产就绪 | 多模型兼容≥75%、格式自检闸门、半自动回归能力 | "稳交付" | 至少在2个不同模型上实测通过率≥75%；报告有格式自检闸门（缺格式退回重生成）；有半自动回归方案（自跑+交叉阅卷） |
| **L5** | 持续优化 | 用户反馈闭环、API自动化回归、pass@k稳定性验证 | "有闭环" | 上架后有真实用户反馈→迭代的闭环通道；API直调脚本可无人值守全量回归；pass@k（同Fixture跑k次一致性）已验证 |

### 升级规则

- **不可跳级**。L1→L2→L3→L4→L5 逐级达成，每级的核心标志全部满足才可晋级。
- **降级触发**：改版后若总分包络（雷达图面积）缩小超过10%，或任一维度跌破该级别门槛，标记为降级风险，需修复后重评。
- **满级 = L5**。L5 不是终点，是「有闭环、能自驱优化」的稳态——持续在 L5 运转、每次改版雷达图不缩即为健康。

## 二、五维评分（每维 20 分，满分 100）

### 维度 1：工程规范度（20 分）

| 分值 | 标准 |
|------|------|
| 20 | frontmatter 全规范（name/description/version/agent_created 无缺）；README 完整；LICENSE 有；.gitignore 有；git 提交历史清晰（每次改版一次提交+规范 message）；文件结构整洁无冗余/临时文件；测试套件可直接运行无报错 |
| 15–19 | 以上基本满足，有1–2项小瑕疵（如临时文件未清理、message 不够规范） |
| 10–14 | frontmatter 有缺字段；或 README 缺失；或 git 历史混乱（一坨大提交） |
| 5–9 | 多项工程规范缺失 |
| 0–4 | 裸 SKILL.md 一个文件，无任何配套 |

### 维度 2：理论严谨度（20 分）

| 分值 | 标准 |
|------|------|
| 20 | 原创概念（五行/三刀/度/鞍点/四象/行动链等）全部有 references/theory.md 释义可回溯；五行顺行（金→水→木→火→土）经案例验证无逆序；自检清单含「不编造概念」约束；references/ 目录完整（theory/diagnosis/cases/api_reference/report_template/visual_templates 齐全） |
| 15–19 | 理论框架完整，1处小瑕疵（如某概念释义不够清晰、某案例与理论有小出入） |
| 10–14 | 有理论框架但部分概念无释义、或顺行有误未修正 |
| 5–9 | 理论框架零散，多处概念无据可查 |
| 0–4 | 无理论体系，纯指令堆砌 |

### 维度 3：交付质量保障（20 分）

| 分值 | 标准 |
|------|------|
| 20 | 四大硬约束全部落地到 SKILL.md（格式自检闸门/取证优先/问题分流/双模式入口）；静态测试≥80项全绿；rubric 10项评分表完整且含★一票否决项；自检清单「不通过=退回重写」非「补一下」；改版后经新一轮多模型实测验证（非仅静态测试通过） |
| 16–19 | 硬约束全部落地+静态测试全绿，但改版后未经新一轮实测验证（静态测试通过≠运行时通过） |
| 10–15 | 有自检清单但不够严格；或静态测试<80项；或缺 rubric |
| 5–9 | 有基本流程约束但无闸门机制 |
| 0–4 | 无任何质量保障机制 |

### 维度 4：跨模型兼容性（20 分）

| 分值 | 标准 |
|------|------|
| 20 | ≥4个不同模型实测通过率100%；pass@k（同Fixture跑3次一致性）已验证；API自动化回归可无人值守全量跑 |
| 16–19 | ≥3个模型实测通过（≥75%），1个模型有已知问题但有修复方案；API自动化未建 |
| 10–15 | 2个模型通过，但模型方差问题未收敛 |
| 5–9 | 仅在1个模型上验证过 |
| 0–4 | 未做任何跨模型测试 |

### 维度 5：可维护性（20 分）

| 分值 | 标准 |
|------|------|
| 20 | 有回归测试手册+≥5个Fixture+自动回归指令模板；有 SMM 评分标准（本文件）且每次改版后评分；有上架检查清单；有用户反馈闭环通道（上架后真实用户反馈→迭代） |
| 16–19 | 有回归测试手册+Fixture+自动回归指令，但缺反馈闭环或缺SMM评分习惯 |
| 10–15 | 有测试但无回归手册；或无自动回归能力（纯手动逐行粘贴） |
| 5–9 | 有零散测试用例但无体系 |
| 0–4 | 无任何可维护性资产 |

## 三、级别与分数映射

| 总分 | 级别 | 含义 |
|------|------|------|
| 90–100 | **L5** | 持续优化——有闭环、能自驱 |
| 75–89 | **L4** | 生产就绪——可上架交付 |
| 55–74 | **L3** | 质量可控——测得过但不够稳 |
| 30–54 | **L2** | 功能完整——能跑但不保证质量 |
| 0–29 | **L1** | 原型——刚能跑 |

> **注意**：分数到线不等于自动升级——还需该级别「核心标志」全部满足。例如80分但没做pass@k，仍是L4不是L5。

## 五、使用方法

### 5.1 何时评

- 每次改版后（version bump）必评一次
- 上架前必评一次
- 用户反馈集中涌入后评一次（看是否需要降级风险预警）

### 5.2 谁来评

- **AI 评**（沐哥心腹）：按本标准逐维打分，出雷达图
- **沐哥审**：看分数是否合理、有没有漏项、有没有粉饰
- **不搞自评自判**：AI 评分，沐哥拍板

### 5.3 怎么记录

每次评分追加到本文件「评分历史」表，并生成一张雷达图与上一次对比：

| 日期 | 版本 | 工程 | 理论 | 交付 | 跨模型 | 可维护 | 总分 | 级别 | 变化 |
|------|------|------|------|------|--------|--------|------|------|------|
| 2026-08-16 | v2.4.1 | 18 | 19 | 16 | 14 | 17 | 84 | L4 | 基线 |

### 5.4 雷达图读法

- 面积扩大 = 进步；面积缩小 = 退化
- 某维度凹陷（明显小于其他维度）= 短板，优先补
- 所有维度均衡且面积大 = 健康；某维度突出但其他塌 = 偏科，有风险

## 六、与其他测试资产的关系

| 资产 | 作用 | 与 SMM 的关系 |
|------|------|---------------|
| `skill_test_suite.py`（86项静态测试） | 检查 SKILL.md 文本是否符合规范 | 项数≥80 + 全绿 → 交付质量维度加分 |
| `evals/rubric.md`（10项评分表） | 人工/AI 阅卷评分报告产出质量 | ★ 一票否决项全过 → 交付质量维度加分 |
| `evals/回归测试手册.md`（5 Fixture） | 改版后回归测试 | 有手册+Fixture → 可维护性维度加分 |
| `evals/自动回归测试指令.md` | 半自动回归（自跑+交叉阅卷） | 有 → 可维护性维度加分 |
| `test_framework.md`（1049行深度参考） | 测试方法论参考 | 深度参考，不直接计入评分 |

SMM 不替代上述任何资产，而是把它们的结果**汇聚成一个数字和一张图**，让「这个 skill 现在什么水平」有标准答案。
